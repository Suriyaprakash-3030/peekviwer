    What the pattern points to

      Session report

      The report fills in as frames arrive or when you open a file.

      Remote viewing Off

      Watch this session from any device, anywhere. This PC (the gateway) relays every frame end-to-end encrypted. Viewers sign in and enter the room passphrase; the relay never sees images.

      Test feed

      No capsule at hand? Replay a recorded .bin file as if it were arriving live over BLE. It takes the same path as real data, so a gateway shares it like a real session. Viewers are told it is a replay.

      One-time Supabase setup
      1. Use the Team plan with the HIPAA add-on, and sign the BAA in the dashboard before any patient data is sent. Encryption alone does not replace the BAA.
      2. Authentication: turn off public sign-ups and create an account for each person allowed to view.
      3. Run this once in the SQL editor. It lets signed-in users join only private rooms named peek1:…:
      create policy "peek1 rooms: receive"
on realtime.messages for select to authenticated
using ( (select realtime.topic()) like 'peek1:%'
        and realtime.messages.extension = 'broadcast' );

create policy "peek1 rooms: send"
on realtime.messages for insert to authenticated
with check ( (select realtime.topic()) like 'peek1:%'
             and realtime.messages.extension = 'broadcast' );

      Then copy the Project URL and publishable key from Project Settings → API. Both are public by design; access is controlled by sign-in and the policies above. Share the room passphrase in person or by phone, never in the same message as the link.
